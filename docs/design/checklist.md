# Checklist

## この文書の役割

この文書は、デザイン文書群と設計成果物の抜け漏れを確認するための文書である。  
ここでは、原則、foundations、components、patterns、screens、tokens、アクセシビリティ、実装引き渡しの観点を確認する。  

## Discovery & Planning

- [ ] `docs/specs/product.md` を確認した
- [ ] `docs/specs/structure.md` を確認した
- [ ] 必要に応じて `docs/specs/api.md` を確認した
- [ ] 仕様を根拠にした画面一覧が網羅的に定義されている
- [ ] 画面一覧と責務が整理されている
- [ ] 画面設計のために仕様を暗黙補完していない
- [ ] 必要コンポーネントを洗い出した
- [ ] 必要 UI パターンを洗い出した

## Foundations

- [ ] テーマ方針がある
- [ ] 色方針がある
- [ ] タイポグラフィ方針がある
- [ ] 余白方針がある
- [ ] レイアウト方針がある
- [ ] 装飾方針がある
- [ ] 文言方針がある

## Components

- [ ] コンポーネントの粒度が定義されている
- [ ] 状態が親コンポーネントに従属している
- [ ] バリエーションが整理されている
- [ ] 禁止事項が明記されている

## Patterns

- [ ] モーダル / シートの使い分けがある
- [ ] トースト / インラインメッセージの使い分けがある
- [ ] 空状態がある
- [ ] ローディング方針がある
- [ ] 確認 UI がある

## Accessibility

- [ ] 色だけに意味を依存していない
- [ ] フォーカスが視認できる
- [ ] キーボード操作を考慮している
- [ ] コントラストを確認している

## HIG / Platform Conventions

- [ ] 対象プラットフォームの HIG または標準 UI 慣習を確認した
- [ ] 入力、メニュー、トースト、モーダル、フォーカスの挙動が不必要に慣習から逸脱していない
- [ ] アイコンは意味が明確な場合だけ使っている
- [ ] 操作対象サイズと間隔が十分である

## Documentation

- [ ] `docs/design/DESIGN.md` が入口として機能している
- [ ] 下位文書の責務が重複していない
- [ ] README から導線がある

## Implementation Handoff

- [ ] tokens が定義されている
- [ ] 実装側へ渡す単位が整理されている
- [ ] 実装時に参照する正本が明確である
