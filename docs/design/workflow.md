# Workflow

## この文書の役割

この文書は、`docs/design/` 配下のデザイン文書群を使って設計を進める順序、前提条件、必須成果物、工程ごとのゲートを定義するための文書である。

ここでは、何を先に定義し、何がそろっていないと次へ進めないかを扱う。  
上位原則は `docs/design/DESIGN.md`、抜け漏れ確認は `docs/design/checklist.md` で扱う。

## 前提条件

- `docs/specs/product.md` が現在の要件を表現している
- `docs/specs/structure.md` が現在の構成と責務分担を表現している
- データ表示や操作契約に影響する場合は、必要に応じて `docs/specs/api.md` を確認する
- デザイン作成前に、`docs/design/` 配下の文書群を確認する
- 文書群に未定義項目がある場合は、ユーザーへヒアリングしながら内容を決める

## 必須成果物

- デザイン文書群
  - `docs/design/DESIGN.md`
  - `docs/design/foundations.md`
  - `docs/design/components.md`
  - `docs/design/ui-patterns.md`
  - `docs/design/screens.md`
  - `docs/design/tokens.md`
  - `docs/design/checklist.md`
- 画面設計成果物
  - 画面の一覧と責務定義
  - 画面遷移図
  - ワイヤーフレーム
- 視覚化成果物
  - カラーパレット
  - タイポグラフィスタディ
  - コンポーネント見本
  - UI パターン見本

## 工程

### 1. 仕様と前提を確認する

- `docs/specs/product.md` を確認する
- `docs/specs/structure.md` を確認する
- 必要に応じて `docs/specs/api.md` を確認する
- 要件、構成、制約に未整理の点があれば先に文書を更新する

### 2. デザイン文書群を定義する

- `docs/design/` 配下の文書群を定義する
- `DESIGN.md` だけでなく、関連する下位文書の未定義項目も整理する
- 色、タイポグラフィ、余白、レイアウト、状態表現、UI パターン、トークン方針の前提をそろえる

### 3. 画面設計の前提を定義する

- 画面の一覧と責務を定義する
- 画面遷移図を作る
- ワイヤーフレームを作る
- 要件から必要コンポーネントを洗い出す
- UI パターンを洗い出す

### 4. 視覚化して確認する

- カラーパレットを作る
- タイポグラフィスタディを作る
- コンポーネント見本を作る
- UI パターン見本を作る

### 5. 画面デザインを作る

- 画面設計の成果物を前提に画面デザインを作る
- 画面側で生じた差分は、必要に応じて `components.md`、`ui-patterns.md`、`tokens.md` へ還元する

### 6. 実装へ接続する

- デザイントークンを定義する
- 実装時に参照すべき文書と成果物をそろえる
- `.pen`、文書、実装の間に不整合がないか確認する

## ゲート

- 前工程の成果物に未定義項目が残る場合は次へ進まない
- 未定義項目に対するヒアリングが完了していない場合は次へ進まない
- 画面一覧、画面遷移図、ワイヤーフレームがない状態でコンポーネント設計や画面デザインへ進まない
- 必要コンポーネントと UI パターンの洗い出しが未完了のまま視覚化へ進まない
- 文書群と不整合なデザインを作らない
