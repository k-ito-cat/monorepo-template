# Components

## この文書の役割

この文書は、再利用可能な UI コンポーネントの定義を管理するための文書である。  
ここでは、コンポーネント一覧、粒度、状態、使用場面、禁止事項を扱う。  
色や余白の値そのものは `tokens.md`、上位原則は `DESIGN.md`、UI パターンは `ui-patterns.md` で扱う。

## コンポーネント設計の原則

- 画面ごとの見た目をそのまま部品化するのではなく、役割と情報のまとまりで部品を切り出す
- コンポーネント、UI パターン、状態を混同しない
- 1 つのコンポーネントがどこまでを含むかを先に定義する
- 一覧や反復要素では、外枠や罫線を含む 1 件全体を部品として扱うのか、その内部要素だけを扱うのかを曖昧にしない
- 状態は単独で扱わず、必ず親コンポーネントに所属させる
- 状態は汎用 UI の一覧から機械的に当てはめず、実務上そのコンポーネントで実際に起こりうるものだけを採用する
- カードや独立した面は、独立した意味、操作、状態、文脈を持つ場合にのみ使う

## コンポーネント作成前の分解

- 要件から必要コンポーネントを洗い出す
- UI パターンを洗い出す
- 洗い出しはヒアリング形式で網羅的に行う
- 未完了のままコンポーネント作成へ進まない
- 思いついた部品から先に作らず、先に必要要素を分解してから作成する

## コンポーネント作成時の必須観点

- 役割
- 構造
- バリエーション
- サイズ
- 状態
- インタラクション
- 開閉や遷移時の見え方
- レスポンシブ時の扱い
- アクセシビリティ
- 内容ルール
- 使用場面
- 禁止事項

## コンポーネントギャラリーの位置づけ

- コンポーネントギャラリーは、見本集ではなく実装引き渡し用の正本とする
- ギャラリーは `docs/design/components.md` の定義をそのまま視覚化するものであり、独自解釈を持ち込まない
- ギャラリーには、実務上起こりうる状態、サイズ差、バリエーション差、パターン差を必ず収録する
- 単体表示だと責務や境界が曖昧になるコンポーネントは、最小限の周辺文脈を付けて表示する
- ギャラリー上の各表示には、名称、状態名、サイズ名、使用場面が対応づくことを前提にする
- 画面固有の装飾差ではなく、再利用単位としての差分だけを扱う
- `sample` や `mock` のような曖昧な呼び方は使わず、`default`, `selected`, `disabled` のような状態名で管理する
- 標準的な図像がある操作やオブジェクトは、文言に加えて icon set の標準図像を併用する
- 上記のアイコン対象は、個別に指示がなくても `Component Gallery` と `screen design` の両方で採用する
- 個別コンポーネントごとの固定対応表は原則持たず、Material Symbols、Lucide、Feather、Phosphor などの icon set から意味が自然に伝わる図像を選ぶ

## ギャラリーで正規化する軸

### パターン軸

- Selection Row: 選択対象を 1 行単位で切り替えるもの
- Navigation Item: ナビゲーション文脈を切り替えるもの
- Section Header: 一覧構造のまとまりを示す見出し
- List Row: 一覧内の 1 行または 1 件を表すもの
- Text Field: 文字入力または文字表示主体のフィールド
- Select Field: 値の選択主体のフィールド
- Button: 主操作または副操作を実行するもの
- Toggle: 表示モードや二者択一を切り替えるもの
- Chip: 小さなタグ、ラベル、削除起点を含む塊
- Meta / Media: 補助情報、補助視覚、識別用の要素

### サイズ軸

- `xs`: アイコンや付属操作のような最小補助サイズ
- `sm`: 軽量な補助 control や chip サイズ
- `md`: 標準 control サイズ
- `lg`: 強調または行単位のサイズ
- `full`: 面やカラム幅に従うサイズ
- 数値トークンが未定義のサイズ差であっても、ギャラリー上では必ず `xs / sm / md / lg / full` のいずれかにマッピングして扱う

### 状態軸

- 基本状態: `default`, `hover`, `focus`, `selected`, `disabled`
- 非同期状態: `loading`, `processing`, `saving`
- 開閉状態: `expanded`, `collapsed`
- 入力状態: `empty`, `filled`, `editing`, `error`
- 表示状態: `view`, `edit`, `placeholder`
- 各コンポーネントは、上記から実務上必要な状態のみを採用する
- ギャラリーには、採用している状態を省略せず全て載せる

## ギャラリー運用ルール

- `wireframe` の段階では、`Component Gallery` の完成見た目を代用しない
- `Component Gallery` は、そのプロダクトで使う部品体系を完成状態で確定する場とする
- `screen design` は、`Component Gallery` の部品を組み立てる工程として扱う
- `screen design` 内で Gallery と異なる色、サイズ、境界、状態差を持ち込まない
- 追加の状態や派生 variation が必要になった場合は、Gallery を先に更新して正本化する
- `Component Gallery` 作成後は、文書群を再帰的に確認し、抜け漏れや方向性のずれを解消してから `screen design` に進む
- 再確認時は、`Component Gallery` が文書を逸脱していないかだけでなく、文書側が古くなっていないかも確認する
