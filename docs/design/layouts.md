# Layouts

## この文書の役割

この文書は、画面内の `Layout 層` を定義するための文書である。  
ここでは、各画面でコンテンツをどのゾーンにどう配置するか、最大幅ではどのような見た目になるか、レスポンシブ時にどのように崩すかを扱う。  
個別コンポーネントの状態や見た目そのものは `components.md`、画面責務は `screens.md` を正本とする。

## レイアウト層の基本原則

- レイアウト層は、コンテンツの中身ではなく `面の分割` と `情報の優先順位` を扱う
- 画面内の主従関係は、色より先に幅、余白、列構成、固定位置で示す
- コンポーネントを置く前に、主要ゾーン、補助ゾーン、一時ゾーンの切り方を確定する
- 画面幅が変わっても、主役の領域がどこかは変えない
- レスポンシブは単なる縮小ではなく、補助ゾーンを `横並び -> シート -> 縦積み` に変換していく
- 各画面は、完成デザインとは別に `layout wire` として視覚化できる状態を保つ

- 画面全体の外枠

- ナビゲーションを束ねるレール

### Content Pane

- 主コンテンツを置く領域

### Inspector Pane

- 詳細確認や軽い編集を行う補助領域

### Toolbar Row

- 検索、フィルタ、ソート、主操作起点を並べる行

### Field Pair Row

- 横並び 2 項目を扱う行

## レイアウト層をビジュアライズするときのルール

- コンポーネント中身は空でもよいが、ゾーン境界、主従、余白差は必ず見えるようにする
- `Desktop Max / Desktop / Compact / Narrow` の少なくとも 3 段階を並べて比較できるようにする
- 比較対象は見た目の装飾差ではなく、ゾーン数、幅配分、重なり方、補助面の扱いの差とする
- Layout wire では、見出しとラベル以外の文言を増やしすぎない
