# docs 運用ルール

## 目的

このファイルは、`docs/` 配下の仕様書と `README.md` を実装や運用と同期させるための運用ルールを定義する。

## 更新が必要な場面

- 機能追加を行った場合
- ディレクトリ構造が変わった場合
- ライブラリの追加や変更を行った場合
- ライブラリを使った機能開発で、手順書の更新や追加が必要になった場合
- 仕様変更、技術方針変更、構成変更、API 方針変更を行った場合
- デザイン関連の構成や方針が変わった場合

## 更新対象

- 機能追加を行った場合は、関連する仕様書を確認し、必要なら更新または追加する
- ディレクトリ構造が変わった場合は、`docs/specs/structure.md` と必要に応じて `README.md` を更新する
- ライブラリの追加や変更を行った場合は、関連する仕様書と必要に応じて `README.md` を更新する
- ライブラリを使った機能開発で手順書の更新や追加が必要になった場合は、`README.md` や関連ドキュメントを更新する
- 仕様変更、技術方針変更、構成変更、API 方針変更を行った場合は、それぞれ対応するドキュメントを放置せず同期する
- デザイン関連の構成や方針が変わった場合は、`docs/design/` 配下をまとめて確認し、必要な文書を同期する

## 更新フロー

- まず更新が必要かどうかを判断する
- 更新要否の判断では、パス参照だけでなく内容整合性も確認する
- docs 構成を変更した場合は、実ファイル一覧と関連ドキュメントの記述を突き合わせる
- docs 構成を変更した場合は、`README.md` と関連する仕様書を横断的に確認する
- docs 構成を変更した場合は、`docs/design/` 配下の責務分担と参照導線も確認する
- 参照パス、用語、現在構成、責務説明のずれを確認する
- 指摘を受けて修正する場合は、同種のずれが他にないか横断的に再確認する
- 更新が必要だと判断したら、対象ドキュメント、更新理由、どのように更新するかを明示する
- ドキュメント更新は、その内容を明示したうえでユーザーの許可を得てから行う

## デザイン作成時の参照ルール

- デザイン作成時は、`docs/design/` 配下の文書群を前提として扱う
- `docs/design/DESIGN.md` だけでなく、`foundations.md`、`components.md`、`ui-patterns.md`、`screens.md`、`tokens.md`、`checklist.md` を必要に応じて横断確認する
- 文書未確認のまま、Pencil や画面デザインの作成へ進まない
- 文書群に未定義項目や未整理の責務が残る場合は、先に文書を更新する
- 文書群と不整合なデザインを作らない
- デザイン更新後は、必要に応じて `docs/design/` 配下の関連文書へ差分を還元する

## 原則

- 実装とドキュメントの乖離を放置しない
- 更新が必要そうな場合は後回しにせず、その場で同期する
- 局所修正で終わらせず、変更の波及先を確認する
